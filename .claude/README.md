# Claude Code workflow for my-nest-app

Проектная адаптация frontend-accelerator-toolset для NestJS backend. Сохранены разделение command → agent → skill, специализация ролей и отчёт по доказательствам. Добавлена координация нескольких стадий в основной сессии. Frontend-роли, Codex-зеркало и отдельный runtime toolchain не устанавливаются.

## Запуск

Откройте новую сессию Claude Code из корня my-nest-app. Если сессия была открыта до появления .claude/agents/, перезапустите её, чтобы загрузились роли.

```text
/nest-feature Добавь фильтрацию пользователей по имени с пагинацией
/nest-bug Refresh token повторно принимается после ротации
/nest-quick Уточни Swagger-описание существующего ответа
/nest-plan Спроектируй logout со всех устройств; код пока не меняй
/nest-review Проверь текущие изменения auth и users
/nest-verify Проверь unit, lint, форматирование и сборку
```

Примеры задают новые задачи только при их фактическом запуске. Для отдельной роли можно попросить: «Используй nest-database, чтобы оценить атомарность ротации refresh token, без изменений». Ролевые навыки скрыты из slash-меню (user-invocable: false), но доступны Claude и предзагружаются в соответствующего агента через skills.

## Сценарии

| Команда      | Маршрут                                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| nest-feature | Критерии → нужные проектные решения → developer → дополнительные тесты при необходимости → reviewer → verifier |
| nest-bug     | Воспроизведение и исправление debugger → reviewer → verifier                                                   |
| nest-quick   | Небольшая реализация developer → verifier; ревью по риску                                                      |
| nest-plan    | Анализ и проектирование без записи                                                                             |
| nest-review  | Только ревью выбранного diff                                                                                   |
| nest-verify  | Только существующие проверки, без исправлений                                                                  |

Роли: nest-analyst, nest-architect, nest-database, nest-developer, nest-debugger, nest-tester, nest-reviewer, nest-verifier. Модель и режим разрешений наследуются из сессии; привилегированные режимы не включаются.

Координатор передаёт специалистам цель, критерии, границы файлов и результаты предыдущих стадий. Один агент пишет в код за раз; до двух независимых read-only анализов могут идти параллельно. Ревью начинается после завершения записи. Не более двух раундов исправлений, затем явный отчёт об оставшихся проблемах. Общие правила: workflows/coordination.md. Контекст проекта и команды: references/project.md. CLAUDE.md остаётся главным источником проектных соглашений.

## Границы и проверка установки

Это инструкции для Claude Code, а не жёсткий движок исполнения. Количество писателей, файловые границы и повторные попытки контролируются координатором по инструкции. Tools у аналитических ролей не включают Edit/Write; Bash остаётся доступен только для описанных операций, поэтому сам по себе не является технической гарантией read-only. Runtime-права продолжают действовать. Hooks, settings, глобальные разрешения, зависимости и исходники приложения этим набором не меняются.

В новой сессии проверьте, что slash-меню показывает шесть nest-команд, и попросите nest-analyst сформулировать критерии для небольшой задачи без правок. Затем попробуйте /nest-plan и /nest-review. Полный feature/bug smoke означает реальное выполнение задачи с проверкой отчётов и изменённых файлов; наличие файлов не доказывает, что агентный сценарий уже прошёл live-проверку.

Текущие HTTP e2e подменяют PrismaService и не доказывают реальную работу PostgreSQL. Миграции, запуск сервисов, коммиты и публикация не выполняются автоматически. Существующий CLAUDE.md и незавершённые изменения проекта сохраняются.

## Источники формата

- https://code.claude.com/docs/en/sub-agents — проектные агенты, tools и предзагрузка skills.
- https://code.claude.com/docs/en/skills — навыки, slash-команды и совместимость .claude/commands/.

Команды оставлены в .claude/commands/ для ясного разделения интерфейса и ролевых навыков; Claude Code поддерживает этот формат наряду с slash-командами из skills. Названия имеют префикс nest-, чтобы не перекрывать встроенные команды.

## MCP для актуальной документации

В корне добавлен `.mcp.json` с HTTP-подключением Context7. Шесть технических ролей получают два инструмента документации и дополнительный навык `nest-library-docs`; существующие локальные инструменты и права записи сохраняются. При новом запуске Claude Code подтвердите проектный сервер штатным способом и проверьте `/mcp`. Подробности: [references/mcp.md](references/mcp.md).

Context7 вызывается для решений, зависящих от версии стороннего API. Claude сначала проверяет установленную версию, затем ищет библиотеку и документацию, сверяет доступную версию и передаёт доказательства дальше по сценарию. Исходники и секреты в запросы не включаются. Качество кода проверяют существующие тесты, lint, format:check, сборка и ревью.
